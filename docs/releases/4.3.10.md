# Fearless Android 4.3.10 (242)

A crash-fix release on the exact 4.3.9 (241) source,
`79564dd784b090df0727257cfad8aed9d81aca60`. Nothing else from the
consolidated line is included. The release ledger records `4.3.10+242=84`:
database schema 84 and every supported migration are unchanged.

## What Play reported

Play Console on 27 November 2026 (data updated 26 November 21:00): a
user-perceived crash rate of 4.13% over the last 28 days, 2.44 points lower
than the 28 days before, against Play's 1.09% bad-behaviour line. The rate
rests on about 1,000 phone sessions, of which about 38 crashed. ANR rate 0.08%.

The list held 32 crash clusters (120 events) and one ANR. Thirty clusters come
from builds that 4.3.3 to 4.3.8 already fixed. Most of the rate is 4.2.0 (229)
devices that have not updated: `ChainDao.observeChainsWithBalanceByName`
alone is 35 events from 15 users, the last four days ago. Those devices meet
4.3.x's requirements (minimum SDK 26 in both), so an update reaches them; no
change to the app can reach the build they run.

In the last seven days: 7 clusters, 17 events. Twelve are the 4.3.7 icon crash
fixed in 4.3.8, one is new on 4.3.8, one is the 4.3.7 `getChain` timeout, and
three are 4.2.0 and 4.0.1. Play's version filter did not yet offer 241.

## Fixes

**Launch clip placement.** The launch clip is placed under aspect-fill and its
offset bounded with `coerceIn(viewWidth - width, 0f)`. Float rounding can make
the filled side a hair shorter than the view (for example 454.99997 for 455),
so the lower bound rose above 0 and `coerceIn` threw from the player's
video-size callback (`LaunchTimeline.kt:87`, `LaunchIgniteOverlay.applyCrop`).
About 6% of view sizes hit it with the 720x1560 clip, and a foldable changes
size whenever it folds. The filled side is now never shorter than the view, the
lower bound never rises above 0, and a size that is not finite gives the
identity. This code is in 4.3.8 and 4.3.9.

**Sky card placement.** `fwSkyPlacement`, which draws the sky behind the
wallet home's hero card, used the same bound and threw for some card sizes
(for example 300x239 with the badge at its usual point). Same fix.

**Late error dialog.** `ErrorDialog.show` called `DialogFragment.show`, which
throws once the fragment manager has saved its state: an error delivered while
the app was going to the background closed it (a 4.2.0 cluster; the code had
not changed since). The dialog is now added allowing state loss and appears
when the user returns; a destroyed manager shows nothing.

Tests: `LaunchIgniteDirectorTest` and `FwIgniteDesignTest` sweep phone and card
sizes, including the sizes that threw; `ErrorDialogRobolectricTest` shows a
dialog after the activity saved its state and finds it on screen after return.
