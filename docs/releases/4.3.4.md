## Why

On 13 November 2026 the owner heard reports of the Android app crashing and asked for the bugs to be fixed. Google
Play's crash list for the last 28 days (read on 13 November, data updated 12 November 17:00 KST) held 28 clusters.
Nearly all came from 4.2.0 (229), which most devices still run while 4.3.3 (235) is at 20%. No cluster named 235 yet.

Also found while reading the code:

- The transaction history keyed rows by operation id, and a later page could repeat an id (a pending transfer that
  completed, two token transfers in one transaction): "Key ... was already used" closed the app. The history keeps
  one operation per id, the newest copy. Viction history used the transaction's index within its block as its id,
  so transfers in different blocks collided; it uses the hash.

## Upgrade safety

No change to keys, signing, storage, the database schema (84), the PIN or WalletConnect. The changes are error
handling, list row identity, navigation ownership, translations and the order of one start-up warm-up. Users
upgrading from 4.2 or older also get everything in `docs/releases/4.3.2.md` and `4.3.3.md`; the Play notes say so.

### Pendulum's runtime now carries a metadata hash

The live check signs a transfer on 13 networks with Mode::Enabled and this app's RFC 78 metadata hash, and asks each
runtime to validate it without submitting anything. Twelve answered `Invalid(Payment)`, the accepted outcome, as for
4.3.3. Pendulum, which the app signs with Mode::Disabled through `MetadataHashExemptions`, also accepted Mode::Enabled:
its spec 27 was built with a hash, where spec 26 answered `Unknown(CannotLookup)`. Mode::Disabled is still accepted, so
the shipped behaviour is unaffected. `5ba34f887` makes the check require what the app relies on (Mode::Disabled
accepted; Mode::Enabled refused for want of a hash or accepted with this app's hash, never `BadProof`). Lifting the
Pendulum exemption would change signing and is left to a reviewed change (`docs/roadmap.md`).
